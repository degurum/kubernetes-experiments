# 認証経路と監査の限界の検証

計画・チェックリスト: [Issue #2](https://github.com/degurum/kubernetes-experiments/issues/2)

このフォルダに、採用する認証方式、最小操作、公開可能な設定例、後片付け手順を追加します。

1. 標準構成でAPI Serverに届く認証要求を観測する
2. 必要な診断ログで監査の不足を補う
3. API Serverへ届く前の失敗を比較する
4. 標準構成の確認後、必要に応じて外部認証へ拡張する
5. API Serverを通らない認証を任意の後続範囲として扱う

RBACの詳細は [別計画](../api-server-rbac/) で扱います。PSAを含むAdmission制御は今回の対象外です。実機検証は未実施で、外部サービス登録や恒久的な認証・権限変更は実施時に対象と範囲を確定します。
